# 未来独立硬件终端

用户已确认未来可以参考 HachimoDock 开发独立硬件终端。当前只保留产品方向和立项条件，不选型定版、不采购、不复制固件，也不把硬件作为软件首发前提。

## 形态比较

| 路线 | 可能价值 | 工程代价与限制 |
| --- | --- | --- |
| USB 桌面配件 | 从软件终端延伸按键、显示和反馈，网络职责少 | 依赖宿主；Android/iPhone USB 能力与供电不同 |
| Wi-Fi 独立终端 | 可直接加入网关，减少对某台电脑的连接依赖 | 配网、设备身份、供电、OTA、媒体和离线行为需完整实现 |
| BLE 小型输入/反馈端 | 适合小数据、低功耗按键或状态 | 音频/素材吞吐、后台连接和跨平台行为要测量 |
| 手机作为显示/输入终端 | 可较早验证交互价值，利用已有屏幕和音频 | 手机后台、占用、供电和安装体验仍有限制 |

Bluetooth 不自动意味着支持音频；BLE GATT 与蓝牙音频是不同链路。Wi-Fi 板卡存在无线协处理器也不证明固件已经提供可用网络协议。

## 复用的软件基础

硬件使用稳定的网关 Device、模型、命令和媒体合同；它与桌面端是不同执行目标。用户客户端通过统一能力发现选择硬件，不能把电脑身份写入硬件冒用。

按实际形态决定 MCU/MPU、屏幕、输入、麦克风、扬声器和存储。HachimoDock 的 P4/大屏动画路线提供一种参考，不能直接推导我们的成本、功耗和体验。无大屏或低功耗路线也要独立比较。

## 立项门槛

1. 软件协同闭环已由真实用户验证，并存在单独硬件带来收益的证据。
2. 使用场景、必需能力、供电/续航、环境、地区和支持寿命明确。
3. 预算覆盖原型、结构、电气、声学、测试、认证、供应链与售后，不只有芯片 BOM。
4. 设备身份注入、签名制品、升级回滚、工厂测试与恢复出厂流程有责任方。
5. 参考素材/固件与第三方组件许可已核验，商业复用取得所需授权。

## 后续工程分期

先用开发板验证协议和交互，再进行工程样机、电气/结构/声学验证，之后才讨论试产和量产。EVT/DVT/PVT 的具体数量、成本和日期由真实项目计划决定，当前不虚构。

每台样机记录 BOM/板型、固件/制品摘要、校准与测试结果。量产前另建制造测试、批次追溯、密钥交付、变更/替代料、合规、维修和停产维护文档。当前 TC-028 仅是未来立项检查计划。
