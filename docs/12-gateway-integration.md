# LimeIoT 接入与上游协作

平台身份、命令、模型、通道与 SDK 归 `limecloud/iot`。产品批准、会话和本机展示归 LimeLink；当前沿正式 `action.invoke` 调用 `link.exchange`，没有私有产品 HTTP 后台。

## 已完成的跨仓配合

IoT 提交 `313090d6b53e28d6e5ad1eaa28d29b8d7c479119` 新增 Swift/Kotlin 显式空间读取与 .NET 10 本地客户端。保留原无参 snapshot 以兼容既有消费者；产品必须明确选择空间。

.NET SDK 提供 HTTPS Cookie/Origin/CSRF、设备能力、类型化动作、原键恢复及有界本地文字任务。平台专项覆盖空间隔离、回执绑定、响应丢失、正文摘要与持久化失败零提交；不将它记作 Windows 窗口验收。

[依赖锁](../contracts/iot-sdk.lock.json)固定精确提交和 123 个 SDK 文件 SHA-256，当前不含工作树覆盖。`tools/prepare-sdk.py --source <明确路径>` 默认从 Git 对象导出；目录里的其他未提交修改不会混入构建。

## 能力状态与边界

| 能力 | 当前产品消费 | 待完成 |
| --- | --- | --- |
| 本地用户会话、空间、设备与模型 | 四端原生核心与工作台 | 完整原生旅程/生命周期验收 |
| 类型化动作与命令恢复 | 完整意图保存、原键 GET、目标核对 | 多故障边界与存储异常验收 |
| MQTT/mTLS 设备通道 | Rust 独立设备子进程，真实网关集成 | 证书续期、自助入网与长期运行 |
| 手机/电脑批准 | 同一所有者下本机批准，120 秒期限、撤销 | 二维码、重配管理和跨账号通用授权 |
| 会话输入仲裁 | 单桌面与创建客户端间 CAS/30 秒租约 | 跨电脑迁移和跨账号共享 |
| AI 文字与语音草稿 | Swift/Kotlin/.NET 文字客户端；系统语音进入草稿 | 真模型质量、网关 ASR、播放与打断 |
| 事件与恢复 | 当前采用显式查询与本机视图更新 | 产品 SSE/gap/游标消费 |
| 受限控制面 | 上游已有部分移动端能力，产品尚未接入 | 桌面授权、四端路由与跨网验收 |

“平台有合同”不等于“产品完整支持”。当前产品动作合同和证据详见[实现记录](29-implementation-and-verification.md)，原研究文件摘要保留在[来源快照](evidence/upstream-snapshot.json)。运行依赖锁与研究快照承担不同责任。

## 实际联合检查

`tools/test-iot-link.mjs` 显式读取指定 IoT 测试工具，创建隔离真实 HTTP/SQLite/Mosquitto 栈，并使用本产品模型与 Rust 执行端。已验证本机批准、重复不产生第二张卡片、原键恢复、展示状态分离、手机/电脑租约仲裁、内容摘要/移除和撤销。

mTLS 用临时独立 CA 与设备证书；记录包含模型、源码和二进制摘要。HTTP 控制器为 Node 签名夹具，不代表移动 App 真机。macOS 另通过真实窗口完成批准、呈现与会话编辑；见[证据索引](evidence/README.md)。

## 后续通用缺口

跨账号批准、桌面原生云授权及通用设备入网向导必须在 IoT 中实现正式合同、兼容和测试。产品不能通过私有网关改版或硬编码 capability 绕过。每个跨仓变更分别提交平台代码与产品消费修订，重新构建实际消费者。
