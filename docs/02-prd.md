# 产品需求 PRD

首版目标是在同一授权空间内，通过网关把手机输入传递给指定桌面执行端，并让两端核对同一任务。需求和验收的机器清单分别见 [requirements.json](requirements.json) 与 [test-cases.json](test-cases.json)。实际实现状态以机器清单和证据为准；跨端卡片只是基础切片，最终 Agent 控制台目标见[部署与 Agent 架构](32-agent-console-architecture.md)。

## 功能范围

| 需求组 | 要求 | 阶段 |
| --- | --- | --- |
| FR-001～FR-004 | 原生桌面/手机入口、明确网关连接和空间选择、客户端与执行身份分离 | P1/P2 |
| FR-005～FR-008 | 桌面执行端注册、短期配对、本机批准、独立撤销 | P2 |
| FR-009～FR-012 | 读取真实能力、明确选目标、发送文本卡片、两端查看同一结果 | P1/P2 |
| FR-013～FR-016 | 保存原请求、丢响应查询、取消区分、事件缺口恢复 | P1/P2 |
| FR-017～FR-020 | 独立终端在线状态、跨端会话接续、同会话写入仲裁、操作记录 | P2/P3 |
| FR-021～FR-024 | 云入口、AI 目录、语音草稿、正文和播放分别授权 | P3/P4 |
| FR-029 | 独立 Agent 执行批准、指定工作目录、运行查询和中断 | P6 |
| FR-025～FR-028 | 有界内容包、数据过期、原生更新、未来硬件接入 | P4/P5 |

P1 阶段只提供已有平台的只读查询与设备合同消费，不能因界面有“电脑”列表就声称已支持电脑执行。文本卡片的动作模型、桌面运行时及产品绑定必须在 P2 完成。

## 最小功能闭环

1. 用户优先发现网关，或选择本机/已保存远程连接，认证后核对空间；连接失败时保留可解释错误。
2. 电脑端申请接入并展示设备身份，所有者在受信端批准。
3. 手机选择在线且声明卡片能力的电脑，输入文本，核对发送对象。
4. 提交前保存原任务意图；网关按当前授权创建单条原命令。
5. 电脑在 LimeLink 自身窗口显示内容，并根据实际观测报告结果。
6. 两端展示同一 command_id 的已受理、已提交或已观测状态。断连后查询原 ID，不自动重发。

## 非功能要求

NFR-001～NFR-008 分别约束身份隔离、最小权限、单一平台账本、隐私保留、生命周期、可访问性与国际化、可复现交付以及可观察性能。具体值、测量条件和失败语义见[可靠性](16-reliability-and-performance.md)。

“只执行一次”是防止产品重复派发的设计目标，不承诺跨文件系统、系统 API 和进程崩溃的物理 exactly-once。无法判断效果时保留 unknown。

## 首版不开放的动作

文本卡片之外的剪贴板写入、文件传输、打开 URL、第三方输入框注入、应用启动、麦克风持续采集和桌面 Agent 派发均需独立能力、权限及验收。应用安装、扫码或一次登录不授予这些能力。

## 放行要求

首个可用版本须通过 P2 所关联的验收用例，包含真实网关、目标操作系统和至少一台手机。SDK 宿主测试、应用编译、模拟 UI 与完整端上运行分别记录。未通过的平台在下载与产品页面准确标为未支持。
