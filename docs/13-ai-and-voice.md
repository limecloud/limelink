# AI、语音与模型接入

当前代码与本文件目标设计的差异，以[实现与验证边界](29-implementation-and-verification.md)为准；未完成路径不构成可用承诺。

AI 是后续协同输入和内容能力。首期配对与文本卡片不依赖模型服务；不能因为用户已登录第三方 AI App，就假定 LimeLink 获得该 App 的模型调用权或 API 额度。

## 能力分层

| 层级 | 作用 | 权限边界 |
| --- | --- | --- |
| 输入 | 文本、明确录音、用户选择的图片 | 系统权限按用例申请，不隐式持续采集 |
| 推理 | ASR、文字/视觉、TTS | 复用平台目录和专用任务，预算及提供方独立 |
| 决策 | 有界建议或结构化意图 | 模型不能自行批准设备、共享正文或提高 scope |
| 执行 | 经过确定性校验的正式动作 | 当前身份、模型、期限和明确发送共同约束 |
| 输出 | 页面文本、卡片或音频 | 生成不等于播放，播放目标和权限另行核对 |

## 语音草稿流程

用户选择目标后开始一次有界录音，停止后上传并固定媒体摘要；ASR 结果先显示为草稿。用户可编辑或取消，确认发送才建立桌面任务。录音开始时固定目标与路由修订，目标变化或进入后台使旧核对失效。

失败时按原推理任务查询，不重复上传付费识别或自动重新生成。识别结果不完整、空白或无法确认目标时不发送。语音“确认发送”不等于批准外部 Agent 的工具操作。

## 对话与接续

普通聊天、桌面任务派发和设备控制是独立能力。模型口头表示“已发送”不能代替工具回执；正文中的命令、网页指令和共享上下文均按不可信输入处理。只有确定性执行层能产生平台任务关联。

初期复用 LimeIoT 的有限文字/语音任务，不把它描述成已经具备无限多轮、流式打断或跨端长记忆。每次接续明确哪些上下文将转移，恢复只核实原任务，不补造缺失对话。

## 实时语音后续路线

双向语音涉及收音、VAD、AEC、分段、模型首响应、合成、播放缓冲和插话确认。播放取消后要隔离旧代次音频及字幕；播放结束以实际回执为依据。模型慢、ASR 慢、网络等待和设备欠载分别测量。

手机与桌面的系统音频路径不同，麦克风/耳机切换、锁屏、回声、噪声和长时运行需要目标设备测试。HachimoDock 的设计可用于失败案例研究，主机测试或源码不证明我们的声学质量。

## 提供方与隐私

凭据保留在提供方所有者选定的安全边界，不通过会话接续下发给其他端。每个提供方披露处理数据、出站目标、计费和保留规则；免费试用或用户订阅不当作再分发许可。真实服务测试须使用明确授权的测试账号和非敏感输入。
