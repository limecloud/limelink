# 实施路线与实际状态

当前已建立四端原生源码与 Rust 执行端，固定 IoT SDK，并取得本地产品核心、真实网关/mTLS 和 macOS 窗口的局部证据。完整发布尚未放行。详细实现见[实现记录](29-implementation-and-verification.md)，机器状态以 [status.json](status.json) 为准。

2026-11-06 按用户要求暂停功能开发，将当前阶段以 `v0.1.0` 开发快照提交并推送 GitHub。该标签固定当前进度，不表示下面的发布阻塞已全部关闭。

本轮方向进一步明确为 Agent 控制台，本机/远程网关和 Agent 执行主机独立，见[部署与 Agent 路线](32-agent-console-architecture.md)。首个 Codex 适配器、运行记录与 macOS 本机批准已完成真实局部联调，见[Agent 执行范围](33-agent-execution.md)；Apple/Android/.NET 设备工具代理、逐次确认与真实网关/模拟灯联调已通过，Windows 目标系统、移动真机和安装仍待推进。

本地配对成功后可直接读取助手配置，三种工作台不再要求先到历史页手动归档。当前 SDK 已实际复验 Apple 工作台、Android/.NET 配对回执与三种客户端无工具 mTLS 协议夹具，见[配对收尾证据](evidence/pairing-receipt-recovery.json)。Android 的普通协同请求可在核实明确终态后自动收尾；成功卡片还需匹配原草稿才清空输入。未知结果仍保留原请求；这些局部通过不解除下面的发布阻塞。

macOS 已补齐本机 Agent 设置，可查找兼容的 Codex、选择目录和权限并保存重连；真实窗口从无 Agent 配置开始完成设备联动，见[设置与任务证据](evidence/agent-settings-macos-ui.json)。Windows 已实现对应设置源码，18 组 .NET 核心与 C# 类型检查通过，见[Windows 设置检查](evidence/agent-settings-windows-core.json)；Windows ACL、完整构建和设置窗口仍待目标系统验证。远程自主设备入网与完整本机网关安装产品尚未完成。

本机网关已有固定提交的离线包和独立 Rust 部署辅助程序。先前隔离安装曾通过 HTTPS、正式设备证书/mTLS 与停止重启检查；当前 SDK 的新目录复验在启动阶段失败，已确认本机 Docker 地址池耗尽，见[本机部署证据](evidence/local-gateway-installation.json)。没有清理用户网络或修改地址池设置。macOS 主网关页与设置共用图形安装/管理入口，旧修订原生启停与执行端连接记录见[窗口证据](evidence/gateway-management-macos-ui.json)，不能推定当前修订完整通过。系统/手机信任、Windows、完整失败恢复和正式更新仍待交付，FR-030 与 TC-030 保持部分完成。

远程安装引导已支持公网和内网参数，使用普通 Linux 原生版本。用户授权的 Ubuntu 22.04 amd64 服务器已实际安装两个非 root systemd 服务，17 项回环 HTTPS、mTLS、私钥隔离及重启检查通过，见[服务器证据](evidence/native-gateway-server.json)。此后已配置网关 DNS、Let’s Encrypt、宝塔 Nginx 和 UFW 8883，公网登录、匿名拒绝、mTLS 与实际执行端上线通过 11 项检查，见[公网证据](evidence/public-native-gateway.json)。远程引导增加明确端口提示与连接检查，3 组网络正反例通过，见[探测证据](evidence/remote-gateway-probe.json)。手机真机与自主入网仍待完成，FR-031 与 TC-031 保持部分完成。

Android 已补齐自动发现网关的源码与选择入口，当前 SDK 的 16 组共享公告解析样例、附加边界检查及 APK 构建重新通过，见[发现证据](evidence/android-gateway-discovery.json)。USB 连接的小米 13/Android 16 已完成公网会话恢复、手机配对申请与电脑原生批准、真实卡片呈现，以及手机发起并在电脑批准的只读 Codex 任务；两端均收到“手机与电脑协同成功”，见[当前手机旅程](evidence/android-mobile-flow.json)。界面精简为助手、协同、设备，单击连接后自动选择唯一空间和电脑；协议编号收进诊断，主界面不要求手工完成请求收尾。系统 NSD、完整前后台/锁屏、设备工具与中断仍待单独验收，iPhone 仍缺完整 Xcode 和真机签名环境。TC-002、TC-029、TC-032 保持部分验收。

最终 UI 包已实际复验 Android 助手和协同两页的键盘布局、导航恢复、成功发送后清空草稿，以及电脑精简安装页的一键安装与连接。安装准备和连接参数默认折叠，诊断信息不出现在常规页面。本轮新卡片最初可见但仍为 queued；临时诊断确认 macOS 没有报告可见窗口。后续窗口恢复可见后，同一张卡片取得 presented 持久回执。当前补充窗口可见性变化监听的源码已构建通过，最小化/恢复完整复验因用户要求暂停而未完成；分阶段证据保持原范围。

本机协同库已补齐主表与缓存回执的正文到期清理，保留原命令和防重放记录；v1 需要明确迁移，WAL 读者释放后可继续清理。16 项协同检查通过，见[正文保留证据](evidence/content-retention.json)。Agent 库另完成清理事务、迟到消息保护、旧空闲页与 WAL 维护，20 项 Agent 检查通过，见[Agent 保留证据](evidence/agent-content-retention.json)。平台账本、客户端、Codex、备份及历史引用容量回收仍需分别处理，完整保留策略仍是发布阻塞。

## 当前发布阻塞

1. 原生窗口与真机覆盖仍不完整；构建不能代替系统生命周期、可访问性和用户流程。
2. 配对采用同一所有者下本机批准，明确重配已有代码；二维码、自主入网、跨账号委派及完整真机流程未完成。
3. 受限云的完整跨网验收、跨电脑接续、网关 ASR/播放仍有缺口。
4. 本机协同库与 Agent 库正文/缓存及活动 WAL 清理已局部验证；平台账本、客户端、Codex、备份及历史引用容量回收仍没有完整产品保留策略。
5. 正式签名渠道、安装更新回退、性能/背压与兼容范围尚未完成验收。
6. 当前 SDK 的无设备工具真实 Codex 三端 mTLS 核心旅程已重新通过，见[真实模型记录](evidence/agent-gateway-live.json)。旧失败保留在[回归记录](evidence/regression-2026-11-06.json)，真实中断与完整生命周期仍未验收；本轮通过不覆盖原生窗口或真手机。窗口可见性恢复监听另有构建通过记录，完整最小化/恢复旅程未完成。
7. 当前 SDK 与入口变化后，部分旧联调证据的修订和源码摘要已不匹配；独立文档检查如实保留失败，不以批量刷新摘要代替复验。手机公网只读旅程另有新证据，不能替代全部旧旅程。

机器追踪保留每项需求的源码与证据；部分实现不标为全面通过，失败与缺失条件不隐藏。按用户后续指令发布的 v0.1.0 是开发阶段快照，不宣称“全部完成”，正式发行状态继续保持 withheld。
