# 测试、验收与证据

验证按范围分层。产品核心、真实 IoT 集成及 macOS 原生窗口已有证据；完整四端旅程仍按用例分别核验。宣传站单独验收；参考项目的测试不能累计到本产品。

## 验证层级

| 层级 | 证明什么 | 不能替代什么 |
| --- | --- | --- |
| 文档检查 | 链接、导航、追踪、JSON 和图源一致 | 功能实现、API 存在或领域结论真实 |
| 合同/纯逻辑 | 数据边界、状态转移和负例 | 系统权限、网络或真实效果 |
| SDK 宿主 | 客户端请求/回执和存储接口 | 完整原生 UI 与生产安全存储 |
| 软件联合 | 真实网关/数据库/协议，生成执行夹具 | 目标操作系统、真实电脑显示 |
| 目标端运行 | 原生权限、窗口、前后台与效果 | 其他 OS/架构、签名发行 |
| 发布验收 | 签名包、安装、更新、卸载、恢复 | 未测试历史版本和真实外部 AI 质量 |
| 硬件/声学 | 指定样机的输入/输出/噪声与持续运行 | 批量制造与法规合格 |

## 必须覆盖的故障

验收清单见 [test-cases.json](test-cases.json)。除正常路径外至少包含错误 origin/空间/用户、重复与过期扫码、并发批准、撤销竞争、丢响应、各进程重启、端侧操作后崩溃、磁盘满、陈旧事件、手机后台与电脑休眠。

目标观察不能只看日志中的“success”。卡片要验证指定电脑和正确原任务的实际显示；submitted 与 observed 分开断言，用户阅读不作为默认可观测效果。

## 联合旅程

P2 旅程由手机选择目标并提交，真实网关受理，桌面执行端接收和显示，两端读取原命令。随后对每个网络边界注入一次回执丢失，验证原键恢复、单条平台命令和零自动重复本机派发。未知结果应保持未知，不通过清空记录让测试继续。

只读查询和副作用测试使用不同夹具。系统权限、安装器、登录项和更新器不得使用现有个人应用或真实数据作为样本。

## 证据格式

每次运行保存源修订与未提交文件摘要、工具链、OS/架构、环境、测试 IDs、开始/结束、通过/失败/跳过、制品摘要和日志引用。跳过说明理由与影响；不同候选包的截图不得混在一个通过结论里。

需求追踪采用 `FR/NFR → DOC → TC → 阶段`。测试计划默认 `not_run`，阶段默认 `not_started`；只有有本产品证据的结果才能修改状态。[status.json](status.json)不引用上游测试作为产品通过依据。

## 文档检查范围

`verify_docs.py` 校验 Markdown 本地链接与锚点、围栏、所有文档入目录、需求/用例/阶段引用、状态一致性、SVG/源码 SHA-256 以及证据结构。源码和 SVG 还需实际渲染与视觉查看；脚本不能证明图形无裁切或领域设计正确。

来源核验基于实际阅读与快照，远端链接未统一做可达性或内容同一性检查。提交前如上游合同更新，重新评估受影响设计。
