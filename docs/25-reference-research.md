# 参考项目研究与借鉴取舍

研究基于本地可读源码和文档，读取日期为 2026-11-05。各项目 HEAD、文件摘要、实际读取范围和未提交差异见[来源台账](evidence/sources.json)与[快照](evidence/upstream-snapshot.json)。这些是观察记录，不能冒充已发布依赖锁或本产品验证。

## LimeIoT

已查证：自研物模型、Rust 网关、命令与恢复合同、HTTP/事件通道、控制面配对、有限远程动作和原生客户端 SDK 均有源码/合同来源。LimeIoTKit 的 Package 明确声明 iOS 17 与 macOS 14。

借鉴与复用：平台事实源、任务恢复和 SDK。边界：桌面 SDK 消费/分发、C# 产品客户端、桌面执行端及跨端路由仍需实现。原生云授权现有限定 ios/android，不能由 Swift 包支持 macOS 推导桌面认证已支持。

## Gootuan

已查证：独立产品仓库管理产品合同、固件、产品应用、工具和联合验收；通过显式 SDK 路径/锁消费平台，并区分软件、样机与整机验收。

借鉴：产品 monorepo、平台/产品所有权、来源固定和逐层证据。取舍：本项目不引入玩具运动、角色或硬件目录，也不复制其与当前产品无关的制造资料。将硬件立项单独延后。

## Shou

已查证：macOS SwiftUI/AppKit 与 Swift Core/Platform、Windows WinUI 3/.NET 10 与 C# Core/Platform/Presentation；共享产品合同、声明式资源和验收案例。系统架构文档的总体 Windows 状态与后续局部验收记录范围不同，不能简单解释为“所有 Windows 功能已完成”或“全部没有验证”。

借鉴：原生平台分层、小型能力接口、确定性共享资源、入口组装和独立验收。取舍：LimeLink 的平台执行核心仍在 IoT，不照搬清理领域、权限策略或各语言重建一套网关。四端维护成本列为风险。

## HachimoDock

已查证：React/Tauri 桌面与 ESP-IDF P4 固件、USB 协同、状态动画、语音和受限组件。当前固件说明没有原生 Wi-Fi/MQTT 路径；桌面能力大量依赖平台适配和当前目标。组件能力与候选能力明确区分，预览和 host 测试不能代替实机验证。

借鉴：即时状态反馈、目标固定、语音草稿、能力协商、资源预算、数据 TTL、事务安装与升级恢复。取舍：当前不复制 Tauri 外壳、USB 依赖、复杂游戏运行时和受限许可素材。未来硬件从需求与预算重新选型。

## 跨项目结论

| 命题 | 结论 | 证据限制 |
| --- | --- | --- |
| 单独产品仓库是否合理 | 合理，产品客户端与系统适配归 LimeLink | 架构决定，不是收益实测 |
| 是否需要另造网关/账号后端 | 当前无必要，复用平台并补必要合同 | 现有权限缺口仍要正式实现 |
| 是否可以统一手机与桌面任务 | 可作为目标设计推进 | 配对、运行时和接续尚无产品实现 |
| 是否立即开发硬件 | 延后到软件需求与稳定合同之后 | 没有成本/市场/量产证据 |
| 是否把参考测试当产品验收 | 不可以 | 本产品实现与运行证据另记，不能累计参考测试 |

本轮不进行各参考工程全量测试，不访问真实账号、家庭设备或生产接口，不把 README 的支持声明升级为已亲测事实。
