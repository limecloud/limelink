# 用户旅程与异常路径

当前代码与本文件目标设计的差异，以[实现与验证边界](29-implementation-and-verification.md)为准；未完成路径不构成可用承诺。

用户围绕“连接、选择目标、发送、查看结果”工作。端点 ID、签名和协议计数用于诊断，不要求普通用户手工填写。

## 首次连接

电脑端展示“连接现有网关”，允许输入受信 HTTPS 地址或使用后续经过验证的局域网发现。发现只提供候选，不建立信任。用户核对网关与空间后完成当前平台登录，再单独申请桌面执行端接入。

手机端连接同一网关或经已授权控制面的入口。扫码包含短期配对引用，不包含长期密钥。批准页展示电脑名称、身份指纹、当前空间、权限和到期时间。审批被拒绝、过期、撤销或账号变化时停止，不回退到默认允许。

## 发送文本卡片

手机先选目标电脑，输入待传内容，发送按钮附近显示电脑名称和空间。提交时冻结目标与文本摘要，落盘失败不发送。电脑实际显示后才能标记“已显示”；仅接收消息时标记“电脑已收到”。

同一请求丢回执时显示“结果待核实”，提供查询原任务入口。重新打开 App 后恢复原任务引用；404、离线和超时都不提供自动换键重发。

## 从电脑切换到手机

初期只共享任务元数据与结果入口，不自动复制完整对话。后续“在手机继续”须选择可共享的片段及目标端，核对当前路由修订。源端已有生成任务保持原 ID，目标端查看原任务；新输入需要新的明确发送动作。

## 取消、退出与撤销

| 用户动作 | 含义 | 应有反馈 |
| --- | --- | --- |
| 取消尚未提交草稿 | 丢弃本地草稿 | 没有创建命令 |
| 停止等待 | 结束本页订阅 | 任务可能继续，可按原 ID 查询 |
| 请求取消任务 | 发送当前能力允许的取消 | 等待执行端确认；不能提前显示已停止 |
| 退出登录 | 撤销当前用户会话并清敏感页面 | 不自动删除执行历史或撤销其他已批准端点 |
| 撤销电脑授权 | 阻止后续获准动作并终止对应输入资格 | 已发送任务按原结果核实，不声称撤回 |

电脑休眠、手机锁屏、网络切换和网关重启均进入[恢复合同](09-tasks-and-recovery.md)，不能在返回时补发过期输入。

## 用户测试检查点

测试人员应能回答当前连到哪一个网关、内容将去哪台电脑、是否已产生副作用，以及哪些结果仍未知。对目标切换、长电脑名、多空间、重复扫码、过期配对和迟到结果分别安排观察任务。
