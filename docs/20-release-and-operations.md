# 发布、运维与支持

当前已有 macOS 开发 App、Android 调试 APK、四端构建工作流和 Windows 开发打包脚本。它们尚未完成正式发行门槛；本文件列出放行和运维要求，[构建试用](30-build-and-local-trial.md)描述实际命令。

## 发布单元

桌面 App、桌面执行运行时、手机 App、平台网关和可选控制面独立版本化。某个 App 包含运行时也要披露各自身份与兼容范围。网关和平台 SDK 版本不跟随产品名称自动升级。

macOS 需核验 Developer ID/公证、签名依赖、权限说明和更新链路；Windows 需核验架构、安装范围、签名、后台服务及卸载行为；iOS/Android 遵循对应分发渠道与权限规则。具体签名账号和渠道尚未选定。

## 兼容与升级

发布说明列出可接受的网关/API、动作模型、SDK 和本机数据格式。升级前检查不兼容项、未决任务和身份材料；不能在副作用未知时清空恢复记录。更换 App 版本不重置或重新派发历史命令。

更新下载校验来源、签名与摘要，安装时段避开不可中断任务。回滚只在旧版本能解释当前数据和凭据时开放；数据库迁移后可能不能直接回滚，须提供受控恢复或升级修复路径。源码回滚不等于用户数据回滚。

## 网关部署

优先消费已经验收的 Linux/NAS 制品，不由桌面安装器隐式修改生产网关、Broker、证书或端口。远程服务沿已有受限出站 WSS，禁止引导用户把原生桌面端口裸露公网。

建议记录产品所用网关版本、部署修订及能力目录时间。服务配置、CA 和身份备份遵守平台合同，用户客户端不持有网关机器私钥。

当前[本机开发部署](30-build-and-local-trial.md#本机网关开发部署)使用固定 Git 源码、独立离线包和实际镜像 ID，不自动拉取新镜像或修改 Docker/DNS 全局配置。容器由用户已有的 Docker 管理，明确启动后持续运行，辅助程序退出不停止服务；停止保留数据。该包为未签名开发制品，尚无正式升级、失败恢复和卸载闭环，不纳入正式安装放行。

远程 Linux 使用[普通原生开发包](30-build-and-local-trial.md#远程-linux-普通版本)，以专用账号运行两个 systemd 服务，独立于 Docker。当前 Ubuntu 22.04 amd64 主机已通过 17 项内部真实检查，见[服务器证据](evidence/native-gateway-server.json)。此后已接通 `https://gateway.link.limeai.run`，使用宝塔已有 Nginx、Let’s Encrypt 与 UFW，公网登录、设备 mTLS 和实际桌面执行端上线通过 11 项检查，见[公网证据](evidence/public-native-gateway.json)。443 复用已有放行，新增 TCP 8883；HTTP 80 用于证书验证及续期。其他站点配置未变，内部 HTTP/明文 MQTT 仍只监听回环。安装包未正式签名；引导生成、内部就绪和公网可用分别记录。SSH 密码不进入界面配置、仓库或证据，用户会话与设备证书保持独立。

## 备份与恢复

产品恢复记录、系统安全存储、设备密钥和平台数据库分别定义责任。备份包含正文时披露加密和保留；导入其他设备不自动复制执行身份。恢复后先核实原任务与当前授权，再允许新输入。

验证空目录恢复、旧数据格式、错误密钥、损坏记录、未决操作和被撤销身份。不能仅验证备份文件可解压就宣称恢复成功。

## 支持与诊断

用户可导出版本、OS、连接阶段和脱敏任务摘要，导出前查看范围。日志不默认包含正文、Cookie、配对秘密和模型 Key。对未知任务的支持流程先查询原操作、核对实际效果，不建议“重新发送试试”。

卸载时明确哪些身份被撤销、哪些记录仍需保留及如何核实未决操作。关闭 UI、退出账号、停用后台和卸载是不同任务。

## 放行清单

指定版本的原生旅程、签名/安装/更新/卸载、兼容矩阵、隐私说明、依赖许可、安全问题处理和用户恢复指南齐备后才能声明支持。用户已要求完成后推送 v0.1.0；当前仍须逐项关闭发布阻塞，不以开发包替代正式支持声明。

2026-11-06 按用户后续指令暂停功能开发，先提交并推送 `v0.1.0` 开发阶段快照。Git Tag 用于固定当前源码、视觉资源和验证记录；正式发行状态仍为 withheld，未通过的检查与目标系统限制保持公开记录，不生成正式签名安装包或商店发行。
