# 安全与隐私设计

当前代码与本文件目标设计的差异，以[实现与验证边界](29-implementation-and-verification.md)为准；未完成路径不构成可用承诺。

安全目标是让每次跨端操作对应当前授权、精确目标和可核实结果。网络内可发现、同账号登录、已连接 USB 或已安装 App 都不能独立授予本机操作权。

## 信任边界

区分用户客户端、桌面执行端、网关、可选控制面、模型提供方和外部内容。通过相应身份认证与受限协议跨越边界，不直接暴露桌面任意 RPC、文件系统或 Shell。外网请求继续受本地网关批准约束。

| 风险 | 防护要求 | 验证 |
| --- | --- | --- |
| 扫到恶意网关或二维码 | 核对 origin、TLS、预期格式和目标空间 | 错源/错空间拒绝 |
| 用户会话被复制到执行端 | 用户与设备凭据分开，设备最小权限 | 存储检查及撤销隔离 |
| 旧配对或旧输入被重放 | 一次性挑战、期限、修订与原请求 | 过期/并发/撤销负例 |
| 模型输出扩大执行范围 | 结构校验、固定能力和当前授权 | 未声明工具与参数拒绝 |
| 日志泄露正文和秘密 | 默认阶段/耗时/错误码，敏感字段不记录 | 脱敏夹具与导出审阅 |
| 本机副作用后崩溃 | 意图先落盘、原记录核实、unknown | 故障注入，不补发 |

## 凭据

macOS/iOS 使用经验证的 Keychain 适配，Windows 使用适当的系统凭据保护，Android 使用 Keystore 支撑的保护方案。实际安全能力取决于实现、用户权限和备份行为，不把“用了安全存储”写成防所有同用户程序访问的保证。

配对秘密、用户 Cookie、设备私钥和模型 API Key 各自保存，日志、二维码、剪贴板和模型上下文不承载长期秘密。原请求恢复记录尽量保存摘要；确需保存正文时，明确加密与保留政策。

## 数据分类与默认处理

| 分类 | 示例 | 策略 |
| --- | --- | --- |
| 连接元数据 | 名称、版本、最近观测时间 | 本地有限保存；导出前允许检查 |
| 执行证据 | command_id、阶段、输入摘要、效果类别 | 按恢复需要保留，不因退出页面而消失 |
| 私密正文 | 卡片、对话、转写、图片与录音 | 最少传输，明确目标，期限与清除独立 |
| 秘密 | 会话、配对 verifier、设备密钥 | 安全存储，禁止进入诊断 |

正文删除、云端删除、任务历史保留和本机未决记录删除是不同动作。尚不能确认远端删除时显示待核实，不能先宣称全部清除。

## 当前协同执行端的正文保留

| 数据 | 当前期限与清理 |
| --- | --- |
| 纯文本卡片、保存内容 | 请求 TTL 为 1 至 86400 秒；到期清空正文 |
| 协同会话 | 请求 TTL 为 1 至 3600 秒；到期清空正文并释放写入租约 |
| `session_claim` 的本机缓存回执 | 创建回执时固定原会话期限；原命令重放也先检查期限，到期清空正文并标记 `content_expired` |
| 原命令、输入摘要、修订和 nonce | 保留原事实及防重放记录；不会为腾空间删除未知任务后重新发送 |

协同数据库使用 `secure_delete=ON`。过期处理在一个事务内更新主表和缓存正文，再尝试截断 WAL。其他读者仍占用旧快照时，运行时视图的 `content_cleanup_pending` 保持为 `true`，后续维护再次尝试；读者的旧快照在释放前仍可能读到正文。数据库重启后会重新检查清理状态。

协同存储格式 v2 保存缓存正文期限。普通启动遇到 v1 返回 `storage_migration_required`，由用户明确运行[迁移命令](30-build-and-local-trial.md#协同数据库迁移)。v1 未记录缓存正文的原始期限，且会话 ID 可能已被重新使用，因此迁移清空旧缓存回执正文，保留当前有效会话正文、原命令和防重放记录。Schema 与身份检查在同一事务内；旧格式空闲页另执行可恢复的整理与 WAL 清理。

[保留检查](evidence/content-retention.json)覆盖原键恢复、过期清理、v1 迁移、身份或损坏数据拒绝、活跃读者与重启，以及活动数据库/WAL 的夹具正文扫描。这个结果不包含客户端安全存储、Agent 数据库、平台命令账本、Codex 会话、备份、系统快照或存储介质副本；完整保留与清除仍未验收。

## 当前 Agent 执行端的正文保留

Agent 库的任务正文、事件、工具设备范围、参数/结果及缓存提案按运行的 1 小时保留期限清空；原运行、命令摘要、游标和防重放记录保留。清理在一个事务内完成，损坏回执会回滚整次清理，修复存储问题后再重试；不会先发送工具回传再留下半份清理结果。维护完成后到达的旧消息不能重新写入已到期正文。

Agent 库启用 `secure_delete=ON`，与协同库共用 WAL 维护逻辑。旧格式没有记录过去是否启用安全删除，因此每次重开既有 Agent 库都安排空闲页整理，再尝试截断 WAL；占用旧快照的读者释放后继续重试。`agent.content_cleanup_pending` 为 `true` 时仍有文件清理待完成，旧读者仍可能读取先前快照。此维护保持现有 v2 表格式，不新增隐式降级或删除原任务。

[Agent 保留检查](evidence/agent-content-retention.json)覆盖事务回滚、旧空闲页、WAL 读者/重启、原引用保持及活动 DB/WAL 的夹具正文扫描。它只验证产品 Agent 数据库，不清除客户端、平台、Codex、备份、系统快照或介质副本，也没有完成历史引用容量回收和统一清除界面。

## 网络与平台权限

正式连接使用经过校验的 TLS，不跟随携带凭据的任意重定向。局域网发现只用于定位，不跳过认证。开发回环例外只在隔离测试中使用，不推广为生产 HTTP。系统辅助功能、通知、麦克风、相机、文件和后台权限逐项按需获取。

## 隐私交付与事件处理

上线前完成数据流清单、第三方处理方、用户告知、保留期限、退出与撤销流程及适用地区评审。当前没有隐私合规认证结论。安全事件先限制相应能力、保留必要证据、撤销受影响身份，再按原任务核实结果；恢复不自动重放历史动作。

TC-023 覆盖秘密/日志与数据清除，跨身份负例分散在配对和任务用例中。
