# 开发与集成路线

当前可执行原生构建、产品核心检查、真实 IoT 联调和文档/视觉/宣传站验证。可复制命令见[构建与隔离试用](30-build-and-local-trial.md)，当前验收边界见[实现记录](29-implementation-and-verification.md)。下面保留实施顺序，未完成出口继续按机器状态跟踪。

## 本轮可运行检查

从仓库根执行：

```sh
python3 "docs/scripts/verify_docs.py"
```

要求 Python 3.10+ 标准库。检查不访问网关、不调用模型、不依赖其他仓库，不删除用户文件。图形渲染工具和版本见[证据说明](evidence/README.md)；普通文档检查无需浏览器或 npm。

## P1：原生只读切片

1. 固定 LimeIoT SDK 来源、路径与所消费的合同快照；准备可复现包或显式开发路径。
2. 建立最小 macOS 原生应用，仅连接隔离 Linux 测试网关，读取空间、设备、能力和原任务。
3. 接入系统安全存储、会话退出与页面取消，验证陈旧响应不能覆盖新空间。
4. 用上游真实网关和模拟设备联调，再在 macOS 原生窗口运行。手机入口先使用明确版本的通用客户端；记录不是 LimeLink 手机 UI。

环境准备不得要求修改全局环境、访问真实家庭设备或共享用户长期凭据。上游工具与依赖安装按照其当时的构建文档执行，不照抄本研究日期的命令。

## P2：桌面执行与手机协同

先冻结卡片动作模型、桌面设备接入和产品配对合同，再实现端侧密钥、受限协议与本机显示。加入手机配对/选择入口后完成一个原请求贯通全部部件。测试使用临时空间、独立凭据和生成文本。

将各进程崩溃点与提交边界绑定，记录原键、command_id、设备身份及结果。故障后只核实，不提供隐式重复发送。没有上游所需权限原语时，先完成接口设计与平台变更，不能跳过授权做 UI 演示。

## 后续平台与扩展

Windows 建立 C# 平台客户端与 WinUI 工作台，Android 建立产品 UI，分别复用正式合同。P3 再实现接续和跨网，P4 再接入语音/内容。每个增量有独立退出标准，不以四端同时开工替代首个完整闭环。

## 本地开发与凭据

所有测试材料放忽略提交的 `.dev/` 或系统临时目录，使用短期最小权限。真实账号、家庭数据和外网提供方测试单独授权。参考仓库只读取证，后续上游修改需要明确记录各仓范围。

## 阻塞记录

记录失败检查、环境/版本、已尝试方案、影响与不依赖项。相同失败最多两轮修复复验；仍失败则保留证据，不降低断言或将 host 测试当端上运行。当前首要阻塞列在[风险与未决事项](22-risks-and-open-decisions.md)。
