# 手机端技术架构

当前代码与本文件目标设计的差异，以[实现与验证边界](29-implementation-and-verification.md)为准；未完成路径不构成可用承诺。

手机是用户输入与协同控制端，通过网关访问获准的桌面能力。首期不要求手机 USB 连接电脑或硬件，也不让手机承担常驻网关。

## 桌面安装与连接

macOS 的“连接手机”入口检测已授权的 USB 设备。Android 安装包由桌面构建显式附带，安装前核验产品包名与 SHA-256；仅更新选定设备，不卸载、不清数据、不在失败后自动重试。手机需开启 USB 调试、允许此电脑，小米等系统还需开启“USB 安装”。系统返回 `INSTALL_FAILED_USER_RESTRICTED` 时，界面明确提示用户处理 USB 安装授权。

安装后通过 `limelink://connect?gateway=…` 交接 HTTPS origin，手机先确认地址，再登录网关。链接不包含访问密钥、会话或设备私钥；收到链接不等于获得授权。桌面和 Android 共用 20 组连接链接正反例。公网地址使用受信 HTTPS；局域网地址的证书信任仍需独立配置。

iPhone 路径需要完整 Xcode、已信任并开启开发者模式的设备，以及包含该设备授权的签名 App。当前环境只有 Command Line Tools，iPhone 安装与真实交接仍未验收。不能将 Android 安装通过推定为 iOS 通过。

## Android 页面组织

使用“助手、协同、设备”底部导航，设置位于右上角。未连接时主操作为“连接电脑”。已有会话自动恢复，只有多个未选定空间或电脑时才要求选择；同一网关内的既有选择可以恢复。请求配对后有界检查批准状态，电脑仍需本机确认；已核实的终态自动收尾，404、未知、异常响应和取消继续保留原请求。

常规页面只显示用户可理解的名称、操作与状态。完整指纹、设备编号、协议状态与原始回执收进设置的诊断信息；共同编辑、内容保存及撤回使用内部保存的引用，不要求填写会话编号、修订或消息编号。核对码只在连接批准时显示，目录和执行权限在任务授权时保留，不能为精简界面取消必要授权。只有多台电脑时显示切换入口。

键盘弹出时收起底部导航，给输入和主按钮留出空间；助手输入框默认三行。执行中的请求不显示“上次操作未确认”，结果区域已有的任务状态不再重复提示。卡片发送草稿仅在原请求已核实成功、完成收尾且当前输入仍匹配原内容时清空，未知结果或新编辑的草稿继续保留。

IoT Android 传输已补齐 GET 连接失败恢复，写请求继续关闭自动重发；正文读取中断会作为异常返回。四项回环故障检查和固定来源核心回归见[传输证据](evidence/android-transport-recovery.json)。公网手机的断流根因尚未由该回环测试证明。

配对和设置面板跳过半展开状态，打开时完整展开，内容保持可滚动。小米 13/Android 16 已完成手机申请、电脑原生批准、公网配对、真实卡片呈现和手机发起的只读 Codex 任务。旧界面证据与本轮旅程分开保留，见[手机协同实测](evidence/android-mobile-flow.json)。

视觉沿用桌面的 Shou 参考方向：浅色 Teal/Slate/Blue 连续渐变、青绿色主按钮、白色按钮文字和现有 3D 品牌插画。颜色由 `tools/generate-desktop-theme.py` 从同一份 Radix 色表生成，不维护第二份手写色值。文字使用 12、14、22 sp 三档，自定义边框 0.5 dp，导航和按钮保留足够触控区域；系统状态栏使用深色图标。品牌位图复用现有原图，本轮没有新增模型生成图。

源码构建、真机安装和实际页面检查分别记录。此次公网只读任务通过不代表系统 NSD、完整后台/锁屏恢复、设备工具、真实中断或 iOS 真机通过。

最后一轮界面精简已通过构建，电脑任务结果页已原生复验。Android 另通过桌面原生安装并打开、一次连接恢复、协同输入时键盘上方按钮、真实发送与成功后草稿清空；电脑前台显示本次卡片并取得持久呈现回执。镜像坐标点击工具仍报 `noWindowsAvailable`，本轮通过键盘完成上述操作；助手输入框的最终键盘布局仍待补测，不能以协同页通过代替助手页通过。

## 原生平台

| 平台 | 建议技术与最低版本 | 消费边界 |
| --- | --- | --- |
| iOS | Swift 6、SwiftUI、URLSession，iOS 17+ | LimeIoTKit、Keychain、系统浏览器与明确媒体授权 |
| Android | Kotlin、Jetpack Compose，API 26+ | 上游 JVM core、受控传输、Keystore 及生命周期 |

最低版本参考现有平台项目，需要在实际产品构建时固定。上游已有 SDK、状态层和页面子集，不代表本产品手机 App 或完整端上旅程已验收。

## 产品归属

P1 可用现有 LimeIoT 手机入口完成平台只读联调；LimeLink 自有的配对、终端选择和协同体验在产品仓库实施。通用 GatewayClient 和命令合同继续归 LimeIoT，发现缺口时补上游，避免复制后各自漂移。

是否发布独立的 LimeLink iOS/Android 安装包在 P1 出口决定。即使暂借通用客户端验证，也必须单独记录产品体验未完成，不能用通用 App 截图充作 LimeLink 交付。

## 生命周期

进入后台、锁屏、离线、退出或切换空间时，清理敏感输入和未提交核对，取消在途页面读取。返回前台重新验证会话、当前关系和原任务，迟到回调不能覆盖新上下文。

iOS 的后台能力和 Android 的前台服务均受系统规则限制。推送只作为提示，点击后读取真实状态；不能保证常驻 WebSocket、无限麦克风或后台任意任务接力。是否使用前台服务须有明确用户任务与独立系统验收。

## 本地状态与权限

会话材料写入安全存储成功后才进入已登录界面。恢复账本至少绑定 origin、主体、空间和原请求摘要；手机安装标识不能被当作用户授权。相机、麦克风、通知和照片选择按实际用例逐项申请，不在首次启动集中索取。

扫码结果只解释允许的配对格式，不直接打开任意网址或向未知主机发送凭据。网关发现、手工地址和云登录的信任判断使用同一原则。

## 音频与第三方应用

首个语音阶段在本产品内录音、识别、显示草稿，明确发送给已选择的目标。手机可使用系统分享能力，但不得声称自动控制任意其他 AI App；原生权限与第三方协议分别验证。
